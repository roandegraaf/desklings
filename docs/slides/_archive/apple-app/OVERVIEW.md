# Schermes for iOS and Mac

> Completed (pending acceptance: 9 items, see ACCEPTANCE.md)

## Goal

A native SwiftUI app for iPhone, iPad and Mac that replaces the MVP web UI as the way the owner
talks to and watches their agents. It talks to the existing daemon API unchanged. The bar is
simplicity and feel: the Grok bot app is the reference, with an iOS 26 Liquid Glass look, one
animated avatar per agent that shows what the agent is doing, and nothing on screen that the
owner does not need in that moment.

## Scope

- One multiplatform SwiftUI project under `apple/`, generated by XcodeGen from `project.yml`.
  iOS 26 and macOS 26 targets share every view; compact and regular layouts are both first class.
- Connect to a daemon by URL. First-run owner setup, login, silent re-login when a session expires.
- Agents: a chat-style list (avatar, name, last message preview, time, unread dot), a pinned row
  of large avatars on top, create, state at a glance, task workers nested under their parent.
- Agent identity: each agent has a body shape and a colour from bloub's catalogue, chosen when it
  is created and changeable later, stored in the app. The daemon has no field for it.
- Chat: an agent's own thread, shared group threads, worker threads. Paged history walking back,
  new rows arriving by poll, the streaming reply (and its reasoning) from `/live` while thinking,
  screenshots inline, tool calls and results readable but out of the way.
- The avatar: a native Swift port of bloub's engine, rendered in a SwiftUI `Canvas`, driven by the
  agent's state. All 14 catalogue states plus `swirl`, gaze drift and blinking at rest.
- Desktop: a native RFB (VNC) client over the daemon's WebSocket proxy. View-only by default, take
  and return control, pointer and keyboard when held, scaled to fit, on every platform.
- Schedules: list, add, pause, resume, delete.
- Settings: provider (base URL, model, API key, extra body), web search (endpoint, key), MCP
  servers as the same JSON textarea the web UI uses, with the per-agent connection test.
- Activity: the agent's execution events as a readable feed, not raw JSON.

## Non-goals

- No daemon API changes. Polling is the contract, as the web UI does it. If a slice proves a
  poll unusable it may add one minimal route and must document why in `docs/architecture.md`.
- No push notifications, no APNs, no relay service.
- No widgets, Live Activities or watchOS. The native avatar makes them possible later; not now.
- No App Store submission, no TestFlight pipeline, no CI. Local builds and sideloading only.
- No bloub montage editor, expression picker, export, or the customiser UI itself. Shapes and
  colours are ported because they are the agent's identity; the rest is not.
- The web UI is not touched or removed in this task.
- No multi-server switching. One saved daemon at a time.

## Key decisions & constraints

- **Swift 6, SwiftUI, iOS 26 / macOS 26 minimum.** Liquid Glass through `glassEffect`,
  `GlassEffectContainer`, `.buttonStyle(.glass)`, glass tab bar and toolbars. No UIKit or AppKit
  views except where SwiftUI has no primitive (keyboard capture for VNC, if needed).
- **Reduce Transparency and Reduce Motion are honoured.** Glass falls back to solid material,
  the avatar keeps morphing but drops decor motion.
- **XcodeGen, not a committed `.xcodeproj`.** `apple/project.yml` is the source; the generated
  project is gitignored. `xcodegen generate && xcodebuild` is the whole build.
- **No third-party packages.** URLSession for HTTP and WebSockets, `Compression` or `zlib` for
  VNC encodings, `Canvas` for the avatar. Swift Testing for tests.
- **API types mirror `shared/src/index.ts` one to one.** Same field names, same optionality,
  `Codable` structs. When `shared` changes, the Swift mirror changes in the same PR.
- **Sessions are the daemon's cookie.** `HTTPCookieStorage` keeps it across launches. The owner
  password goes in the Keychain so an expired session re-logs in silently; one failure shows the
  login screen.
- **Plain HTTP is allowed.** App Transport Security is opened for arbitrary loads and the reason
  is stated in `apple/README.md`: the daemon speaks HTTP by design and TLS belongs to a proxy in
  front of it. The connect screen recommends `https://` for anything off the local network.
- **The avatar is a port, not a wrapper.** Port `src/bot/{math,repere,profiles,shape,face,
  expressions,decor,states,skins,eyefit,engine}.ts` from bloub at commit
  `b4bb3c1b5f93c7b87a2e8d620f667c4093d97749` (MIT, `github.com/jeremy-prt/bloub`). Keep the
  measured constants byte for byte and the engine a pure function of time. `skins` gives the 8
  body shapes and 12 colours; `eyefit` is the precomputed eye-offset table those shapes need and
  is solved once at startup, never per frame, as bloub's architecture doc insists. Skip `cycles`.
  Credit and licence text ship in the app's about screen.
- **Agent identity is local.** Shape and colour live in the app, keyed by agent name, with a
  deterministic default from a hash of the name so an agent seen for the first time already
  looks like itself. Unread state is a local last-seen message id per thread.
- **Last-message previews are one request per agent** (`?limit=1`) on the list poll. Fine for
  the handful of agents one machine runs; a `lastMessage` on `GET /api/agents` is the upgrade
  path if it ever hurts, and would be the one daemon change this task allows itself.
- **Agent state to avatar state** is one table in one file: `thinking` → `thinking`,
  `using_computer` → `orbit`, `using_terminal` → `comet`, `waiting_for_user` → `notify`,
  `waiting_for_agent` / `waiting_for_task_worker` → `wide`, `failed` → `exclaim`,
  `completed` → `sleep`, `idle` → `idle`. Adjust by taste later; keep it a table.
- **VNC is a hand-written RFB 3.8 client.** Security type `None` (that is how Xvnc is started),
  32-bit BGRX pixel format requested so rects blit straight into the framebuffer, encodings
  `Raw`, `CopyRect` and at least one zlib-based one (`ZRLE` or `Tight`). The framebuffer is one
  `CGContext`; the view redraws at most 60 times a second. Input is sent only while the daemon
  says this viewer holds control, exactly like the web UI: the proxy filters nothing.
- **Polling cadence copies the web UI.** Agents every 2 s, live reply every 1 s while thinking,
  control and events every 4 s while the desktop is open. Everything stops in the background.
- **Design language, from the Grok Bot reference screenshots.**
  - The list screen: a small owner avatar top left, search and plus top right as glass circles,
    a horizontal row of pinned agents as large avatars with names, then a grouped list of
    conversations with avatar, name, preview, time and an unread dot.
  - Chat: a glass pill in the toolbar with the agent's small avatar and name, owner messages as
    dark bubbles on the right, agent messages as light bubbles on the left, date separators and
    a "new" divider at the first unread row, tool traffic collapsed to one line per call, and a
    floating glass pill composer with plus and mic. A screen button in the toolbar opens the
    desktop on compact widths.
  - Desktop on iOS: full-bleed dark screen, the agent pill and a back button top left, keyboard
    and more buttons top right, the framebuffer letterboxed in the middle.
  - Mac and iPad regular width: three columns. Agent list as sidebar with search, chat in the
    middle, and an inspector on the right with the live desktop as a thumbnail that expands, and
    the schedules listed as "Routines" with their cadence and paused state.
  - Light and dark both first class. Settings behind one gear, plugins (MCP) as a row at the
    bottom of the sidebar.

## Preconditions & external dependencies

- Xcode 26.x with the iOS 26 simulator runtime, present on this Mac (26.6 / iOS 26.5).
- XcodeGen on `PATH`, present (`/opt/homebrew/bin/xcodegen`, 2.44.1).
- A running daemon to talk to: `docker compose up -d` in this repo gives one on
  `http://127.0.0.1:7777`. Agent desktops in the harness are needed for VNC and screenshots.
- A real OpenAI-compatible endpoint and key, set in Settings, to see the avatar cycle through
  real turns. The scripted stub in `infra/provider-stub.py` is enough for the reply path.
- An Apple developer team, free personal team included, to run on a physical iPhone. The
  simulator and the Mac target need nothing.

## Building blocks

- `apple/project.yml`, targets, entitlements, ATS, Info.plist, `apple/README.md`.
- `Api/`: `SchermesClient` (URLSession, cookie session, JSON, error envelope), `Types.swift`
  mirroring `shared`, a `Session` observable that owns the server URL, auth state and pollers.
- `Bloub/`: the engine port and `BloubView`, with the state table and the golden tests.
- `Vnc/`: `RfbClient` (framing, handshake, encodings), `Framebuffer`, `DesktopView`, input
  mapping including X11 keysyms.
- `Views/`: connect and gate screens, agent list and sidebar, chat with composer and live reply,
  desktop, schedules, settings, activity, about.
- Tests: JSON fixtures decoded against the Swift mirror, engine goldens ported from
  `engine.test.ts`, RFB parsing on canned byte streams, keysym mapping.
